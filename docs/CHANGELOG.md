## Correção cirúrgica — token de sessão e confirmação de snapshots (2026-11-14)
- **Bugs:** o lock verificava apenas serverId; clone/validação descartavam sessionId; loads sobrepostos podiam adquirir duas sessões; confirmação reconstruía o estado atual após o yield do UpdateAsync; retorno sem erro podia confirmar uma escrita cancelada/divergente; lastPersistedData podia receber alterações apenas em memória.

- **Propriedade:** GUID gerado antes da aquisição, preservado no schema, clones, snapshots, fallback e recuperação. Cada callback de save/retry/release exige serverId E sessionId. Lock ativo de outro servidor ou token é preservado; no load normal, lock com timestamp inválido é tratado como expirado com aviso; na verificação de recuperação por snapshot, lock externo sem timestamp finito é recusado conservadoramente. Legado sem token pode ser adquirido atomicamente quando local ou expirado; legado externo ativo não é sobrescrito. A expiração continua conforme Config.

Retorno nil/divergente não confirma. lastPersistedData recebe cópia do payload confirmado, nunca reconstrução do estado atual.
